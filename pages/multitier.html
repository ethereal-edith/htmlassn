Multitier Architecture

Multitier architecture divides an application into layers so each part has a clear job.

TierRoleExample
PresentationUser interfaceBrowser
LogicBusiness rulesApplication server
DataStores informationDatabase

Key idea: separating layers makes systems easier to build and manage.

Admission Number: 220965

Benefits

  • Separation of Concerns — each tier has a specific role; changes in one tier don't break others
  • Scalability — individual tiers can be scaled independently based on demand
  • Security — the database tier is never directly exposed to the user; the app tier acts as a gatekeeper
  • Maintainability — different teams can work on different tiers simultaneously
  • Reusability — the same application/data tier can serve multiple presentation interfaces (web, mobile)
  • Testability — each tier can be tested in isolation with unit and integration tests

Beyond Three Tiers

Modern applications often extend the classic 3-tier model:

2-Tier (Client-Server)

The client communicates directly with the database. Simpler but less secure and scalable. Common in desktop applications.

4-Tier

Adds a delivery tier (CDN, load balancer, API gateway) in front of the presentation layer.

Microservices

A modern evolution where the application tier is split into many small, independently deployable services that communicate via APIs.

Real-World Example

An e-commerce site: React frontend (Presentation) → Django REST API (Logic) → PostgreSQL (Data).
